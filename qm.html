01 / CORE VERDICT

隔离只是基础，完整核心有四层

权限决定这一轮“不能看到什么、能装配什么、允许做什么，以及做过什么如何留痕”。

01

隔离

Scope Boundary

个人、群聊、频道、团队和组织资源默认分离；当前空间是可写层，上层资源按规则只读挂载。

02

装配

Permission Projection

根据参与者共同权限，将文件、记忆、Skills、凭据和网络边界投影到本轮运行环境。

03

执行

Deterministic Gates

Agent 提出行动；命令策略、审批、预算和出网控制在模型之外决定是否执行。

04

持久

State & Audit

会话、工作区、进程、后台任务和审计跨 Turn 保留，让组织工作不依赖一次聊天上下文。

02 / TURN LIFECYCLE

一次请求怎样变成受控执行

同一条链路服务人类消息和后台自动任务；自动化不会绕过 Scope、权限、凭据或命令策略。

  1. 01Surface

    接收消息

    Slack 或 Web 转换为 actor、conversation 和输入。

  2. 02Identity

    确认主体

    检查内部身份、参与者、成员版本、速率和预算。

  3. 03Resolution

    计算边界

    解析 Scope、Workspace Layers、ACL、出网和安全策略。

  4. 04Projection

    装配资源

    加载共同可见历史、记忆、文件、Skills 和凭据 Grant。

  5. 05Harness

    选择 Agent

    在组织批准范围内路由 Codex、Claude Code、OpenCode 或 Pi。

  6. 06Sandbox

    受控执行

    命令先经 deny/approval，再进入当前 Scope 的持久计算机。

  7. 07Persistence

    保存与投递

    写入会话、记忆、任务状态、文件和审计，再返回原入口。

04 / SECURITY BOUNDARY

Scope 降低风险，但不等于已经安全

上游明确把 QM 定义为早期实验软件。命令规则、内容筛查和审计都是纵深防御，不是安全认证。

命令策略可绕过

文本分类能挡常见错误，但编码、混淆或先落盘再执行脚本仍可能规避规则。

凭据使用时为明文

环境变量和文件进入沙箱后可被进程读取；purpose 目前不是强制授权约束。

安全筛查覆盖不完整

命令输出、多模态、部分 webhook 和混合权限上下文仍存在已知缺口。

管理员是特权读取者

管理员可以审计地读取大量敏感内容；持久数据也可能超过用户预期长期保留。

ADOPTION POSTURE

研究优先，PoC 受控，生产暂缓。
