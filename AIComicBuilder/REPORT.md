# AIComicBuilder 研究与接入报告

> 研究日期：2026-08-09
> 上游项目：<https://github.com/LingyiChen-AI/AIComicBuilder>
> 本地定位：`0807_githubcode_study` 的独立子项目
> 结论状态：Windows 安装、MiniMax 接入、Codex 控制、外部视频接力、两条完整样例均已验证

## 一、结论先行

AIComicBuilder 不是一个能够独立承担编剧、导演和审片职责的“AI 导演”，也不是一套解决故事质量的编剧理论。它是一套把 AI 漫剧/短剧生产步骤固定化的可运行工作台：负责保存项目、分集、角色、分镜、关键帧和视频资产，并按照预设动作调用文本、图片和视频模型。

它最准确的产品定位是：

> **AI 短剧生产执行系统，而不是故事创作决策系统。**

它解决“怎样把已经认可的创意方案生产出来”，没有完整解决“什么故事值得拍、怎样拍才好看、生成结果是否合格”。因此推荐的总体架构不是让它独立全自动运行，而是：

```text
ChatGPT / Codex 主创与控制层
  ├─ 故事开发、人物圣经、分集、导演方案
  ├─ 审批、预算、模型路由、失败判断
  └─ 视觉审片、连续性检查、返工决策
                    ↓
AIComicBuilder 生产执行层
  ├─ 项目/分集/分镜/版本/资产状态
  ├─ 调用文本、图片、视频模型
  ├─ 外部网页接力与视频导入
  └─ 镜头拼接、字幕和素材下载
                    ↓
外部生成模型与本地 FFmpeg
```

本次研究的主要价值，是确认了这个边界，并将 Codex 作为安全控制入口接入，而不是只在网页中不断点击“批量生成”。

## 二、它实际拥有的能力

| 环节 | 当前能力 | 结论 |
|---|---|---|
| 项目管理 | 项目、分集、角色、场景、分镜版本、镜头资产 | 可用，适合单机制作管理 |
| 故事输入 | 手写、导入文档、AI 大纲、AI 剧本 | 能产出初稿，不负责质量判断 |
| 自动分集 | 根据导入内容拆分分集 | 属于模型辅助，不能替代分集策划 |
| 角色开发 | 从剧本提取角色、生成视觉描述和角色参考图 | 可用，但一致性取决于图片模型 |
| 分镜 | 将剧本拆成镜头、构图、运镜、时长和对白 | 可用，必须增加镜头预算和人工审批 |
| 关键帧 | 首尾帧模式、场景参考图模式 | 可用，人物近景和复杂动作风险较高 |
| 视频提示词 | 结合镜头信息和参考图生成 | 可编辑；模型生成不等于可拍摄 |
| 视频生成 | Seedance、Kling、Veo、Wan 等适配器 | 依赖外部服务和账户能力 |
| 外部视频接力 | 复制提示词、下载参考帧、上传网页生成的视频 | 本地分支已验证，可替代暂时缺失的视频 API |
| 合成 | FFmpeg 拼接、部分转场、字幕 | 可完成预览，离专业后期仍有距离 |
| Codex 控制 | 计划、审批、执行、重试、取消、状态查询 | 本地分支已实现 MVP |

## 三、它没有真正解决的问题

### 1. 剧本质量

仓库内置了大纲、剧本和自动分集动作，但本质是预设提示词加一次或多次大模型调用。系统没有完整的戏剧质量模型，不能可靠判断：

- 主角目标和阻力是否清晰；
- 冲突是否升级；
- 人物行为是否符合性格；
- 每集钩子和情绪转折是否有效；
- 多集伏笔、回收和人物弧线是否连续；
- 剧本是否适合当前视频模型实际生成。

所以 AIComicBuilder 可以“生成剧本文件”，但不能为剧本质量负责。正式使用时，故事开发应在进入生产流水线前完成，并设置人工或 Codex 审批门。

### 2. 导演与表演

系统能生成镜头描述和运镜提示，但不会理解一段表演是否自然。人物视线、微表情、手指、口型和双人互动，依然是现阶段视频模型的高风险区域。

本次真人花店实验中，首尾帧只改变瞳孔方向，外部视频模型把差异插值成“眼球横向滑动 + 轻微换脸”。技术调用成功，但艺术结果失败。这说明系统需要视觉审片与动作风险分类，不能只以接口返回成功作为完成标准。

### 3. 人物一致性

图片适配器对参考图的支持并不一致：

- Gemini 图片实现会实际发送多张参考图；
- 当前 OpenAI 兼容图片实现只发送提示词，没有发送角色参考图；
- Kling 和 DashScope 图片实现也没有完整使用 `referenceImages`；
- MiniMax `image-01` 本地适配只保留第一个可用主体参考；遇到特定参考图错误时会降级为无参考生成。

因此界面中存在角色参考图，不代表底层模型一定收到了相同信息。长故事必须增加人物圣经、固定锚点图、镜头级连续性清单和生成后视觉检查。

### 4. 自动审片

当前状态系统主要检查请求是否完成、文件是否存在，不能自动确认：

- 人脸、年龄、发型、服装、饰品是否漂移；
- 道具数量和空间位置是否变化；
- 是否出现额外人物、肢体或文字；
- 动作是否诡异；
- 音频、对白和口型是否正确；
- 镜头之间是否连续。

这是从“演示工具”走向“稳定生产系统”最需要补齐的能力。

## 四、本次完成的接入与增强

### MiniMax

- 新增 `minimax` 文本/图片协议；
- MiniMax M3 默认关闭 thinking，避免 `<think>` 内容污染 JSON；
- 支持 M3 图片和视频输入理解；
- 支持 `image-01` 图片生成；
- 参考图请求失败时有限降级，避免任务完全中断；
- 流式文本输出增加严格完成检查，长度截断、错误或中断不再保存为成功结果。

MiniMax M3 在本项目中的合理职责是大纲、剧本辅助、角色提取、分镜、提示词、图片/视频理解和质量分析。它不是视频生成模型；图像、语音、音乐和视频应分别使用对应的独立模型或外部服务。

### Codex 控制入口

- 增加 `comicctl` 命令行控制面；
- 增加 orchestrator run 数据和 API；
- 支持 dry-run、审批、执行、重试、取消和状态查询；
- 支持 `providerProfileId`，任务记录不保存 API Key；
- 支持幂等键和默认 3 路全局并发限制；
- 应用重启后将遗留运行任务标记为失败，允许检查后重试。

Codex 只通过 CLI/API 控制，不直接修改 SQLite。浏览器仍然是可视化审阅器，数据库和上传目录继续作为生产事实源。

### 外部网页视频接力

当用户没有可配置的视频 API、但拥有第三方网页账户时，本地分支增加了：

- 复制当前镜头视频提示词；
- 单独打开或下载首帧、尾帧、场景参考图；
- 显示实际画幅和镜头时长；
- 上传 MP4、WebM 或 MOV；
- 将外部视频作为新的镜头资产版本登记；
- 保留来源、文件大小、类型和导入时间元数据。

这使网页模型可以临时充当“人工视频 Provider”，但仍不适合大规模自动生产。

### 提示词和稳定性修复

- 修正剧本和分镜中的时长/镜头数冲突；
- 用户指定镜头数时按硬约束处理；
- 视频提示词限制为一个连续镜头、一个主运镜和 1–2 个动作节拍；
- 修正角色图、场景图和视频提示词中的引用顺序；
- 首尾帧模式与场景序列模式使用不同约束；
- MiniMax 图片提示词增加长度预算和参考图降级处理。

## 五、两个完整样例

### 样例一：AIComicBuilder 流水线样例

- 成片：[`docs/samples/sample-01-aicomicbuilder-pipeline.mp4`](docs/samples/sample-01-aicomicbuilder-pipeline.mp4)
- 时长：31.05 秒
- 画幅：9:16
- 镜头数：6
- 内容：雨夜室内的动画女孩绘制发光星星
- 目的：验证项目、分镜、首尾帧、外部视频接力、逐镜导入、声音和最终拼接
- 结果：完整流程可走通；角色服装与空间整体连续，但逐镜画风和面部仍需要审片

### 样例二：ChatGPT 主创样例

- 成片：[`docs/samples/sample-02-chatgpt-directed.mp4`](docs/samples/sample-02-chatgpt-directed.mp4)
- 时长：20.77 秒
- 画幅：9:16
- 镜头数：4
- 内容：雨夜温室中的铜质幼苗机器人，让空花盆长出新芽
- 目的：验证由 ChatGPT 负责故事、导演、美术、首尾帧和视频提示词，外部网页只负责生成运动
- 结果：人物与场景一致性明显更稳定；非人类角色、单一场景和清晰动作更适合当前模型

两条仓库视频均由 1440×2560 原始样片压缩为 720×1280、H.264/AAC，并保留原始纵向比例和声音，适合代码仓库审阅。

### 未作为正式样例的真人实验

《凌晨四点的花店》建立了两名真人角色、固定花店场景和连续镜头。前两镜验证了真人外貌、服装、眼镜、身高关系和唯一向日葵的连续性；第三镜暴露了眼球运动的恐怖谷问题。

这个失败结果没有作为最终样例提交，但形成了可复用规则：

1. 不用两张独立生成的人脸去插值微表情；
2. 眼神变化优先通过切镜表达；
3. 单图视频只保留呼吸、眨眼或环境变化；
4. 人物近景失败时先改导演方案，不先增加提示词长度。

## 六、推荐的标准生产流程

```text
1. 主创开发
   故事目标 → 人物圣经 → 世界/场景圣经 → 分集大纲 → 可拍摄剧本

2. AIComicBuilder 建档
   项目 → 分集 → 角色 → 场景 → 分镜版本

3. 文本生产
   大纲/剧本辅助 → 角色提取 → 分镜 → 人工或 Codex 审批

4. 视觉锁定
   角色锚点 → 场景锚点 → 一个镜头的首尾帧 → 审批

5. 视频试制
   一个镜头 → 抽帧审查 → 最多有限重试 → 通过后扩展

6. 批次生产
   每次 1–3 镜，保持 2–3 路外部并发，失败镜头单独返工

7. 合成
   确认完成镜头数 = 总镜头数 → 标准化编码 → 拼接 → 字幕/声音检查
```

每个阶段都应把数据库中的当前项目、版本、镜头和活动资产作为事实源，而不是依赖聊天记忆或网页当前状态。

详细控制架构见 [`docs/CAPABILITY_CONTROL_ARCHITECTURE.md`](docs/CAPABILITY_CONTROL_ARCHITECTURE.md)，可复现操作见 [`docs/SAMPLE_PRODUCTION_GUIDE.md`](docs/SAMPLE_PRODUCTION_GUIDE.md)。

## 七、限制与风险

| 风险 | 当前表现 | 建议 |
|---|---|---|
| 故事质量 | 只有生成，没有体系化评审 | 增加主创开发层和剧本评分/审批 |
| 人物连续性 | 依赖 Provider 是否真正发送参考图 | 建立角色锚点、参考图路由和视觉 QA |
| 视频表演 | 眼神、手、口型和双人互动不稳定 | 镜头风险分类，优先剪辑表达 |
| 任务可靠性 | 控制器为本进程执行，重启不能续跑 | 后续改为持久队列和 Provider 任务查询 |
| 并发与费用 | 部分批量动作内部使用并行调用 | 生产控制器限制 2–3，单镜先验收 |
| 合成完整性 | 缺少镜头时仍可能拼出部分成片 | 合成前增加 N/N 硬门禁 |
| 音频 | 非硬切转场路径会移除原声 | 有原声的初版全部使用硬切 |
| 版本对比 | 当前对比 UI 仍为占位逻辑 | 实现按版本独立取数和差异比较 |
| 安全 | `x-user-id` 仅适合本机，浏览器配置可含密钥 | 不暴露公网；使用服务端 Profile 和正式认证 |
| 存储 | SQLite + 本地 uploads | 长期生产迁移到数据库和对象存储 |

## 八、是否适合更长故事

数据模型支持项目、分集、跨集角色和分镜版本，因此没有“只能做几十秒”的硬性故事长度限制；真正的限制来自每个镜头的短视频生成、资产数量、连续性检查和任务可靠性。

扩展到多集短剧需要增加：

- 系列圣经、人物弧线和跨集连续性账本；
- 场景、服装、道具和时间线的结构化状态；
- 每集制作预算和镜头风险预算；
- 自动人脸/服装/道具/字幕/音频检查；
- 持久任务队列、对象存储和可恢复 Provider 任务；
- 专业配音、口型、音乐、混音和时间线输出。

扩展到电影级别则不能只继续增加模型调用次数，而要把它升级为完整的制片与后期系统。

## 九、最终采用建议

推荐保留 AIComicBuilder 作为独立子项目和生产执行底座，继续维护本地增强，但不把它视为独立导演或编剧。

推荐职责划分：

- **ChatGPT/Codex**：主创、导演、制片控制、审片和返工决策；
- **AIComicBuilder**：项目/分集/镜头/资产状态与自动化执行；
- **文本模型**：草稿、提取、分析和提示词；
- **图片模型**：角色、场景和关键帧；
- **视频模型/网页**：短镜头运动；
- **FFmpeg/后期工具**：标准化、合成和交付。

下一阶段最值得投入的不是继续增加故事样片数量，而是补齐“主创开发层 + 自动审片层”，形成：

> **AI 编剧室 → AIComicBuilder 生产执行 → 自动审片与返工**
