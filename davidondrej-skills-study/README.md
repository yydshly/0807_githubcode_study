# David Ondrej Skills 能力储备档案

上游仓库：[davidondrej/skills](https://github.com/davidondrej/skills)

直观专题页：[David Ondrej Skills 能力雷达](../davidondrej-skills.html)

## 一句话判断

这是一个覆盖 Agent 编排、研究、运维、技能开发和思考文档的个人 Agent Skill 样本库。它最适合作为**工作流设计参考与候选能力目录**，不适合未经审查地整库安装。

## 对我们的意义

### 1. 建立“遇到问题先找流程”的能力储备

仓库把很多重复问题写成了可检索的 SOP，例如长期目标循环、多代理并行、工作交接、研究提示词、部署守护、数据库只读访问和项目决策澄清。未来遇到类似任务时，我们可以先查阅对应技能，再决定复用、改造还是自行实现。

### 2. 学习怎样把经验写成 Agent Skill

上游最有普适价值的不是某个工具，而是技能的组织方式：用 `description` 做路由，用 `SKILL.md` 固化流程，把确定性逻辑下沉到脚本，用参考资料做渐进式加载，并明确验证、失败处理和安全边界。

### 3. 识别我们现有能力的空白与重叠

本档案把每项能力分成四类：

- **优先吸收**：方法通用、依赖少，值得进入我们的工作规范；
- **改造后用**：方向有价值，但要替换作者的路径、工具或权限模型；
- **条件储备**：只在特定平台、服务或项目出现时启用；
- **不原样用**：高度绑定作者个人环境、生产系统或高风险动作，只保留设计参考。

这样可以避免重复安装已经由 Codex、现有插件或当前技能覆盖的能力。

### 4. 提供安全与可验证性的反面教材和正面样本

上游包含危险命令守卫、只读数据库角色、明确停止条件等好做法，也包含生产推送、杀进程、个人目录、账号密钥和外部付费服务等高风险或强耦合流程。两类内容都值得保留：前者可以借鉴，后者提醒我们技能必须经过来源、脚本、网络、写入范围和权限审计。

## 关联方向与后期使用场景

它在能力表面上很像 Codex 这类通用 Agent，是因为它整理的正是通用 Agent 经常需要的工作方法。但两者所在层级不同：Codex 提供模型、工具、运行环境、权限和交互入口；这个仓库主要提供可复用的流程、约束、提示、检查表和少量脚本。对我们而言，它更接近一份“个人 Agent 系统配置蓝图”。

| 关联方向 | 可参考的能力 | 后期适用场景 | 我们的采用方式 |
|---|---|---|---|
| Agent 编排与长任务 | `goal-loop`、子代理、`handoff`、`git-worktree` | 跨多轮研究、长期编码、多任务并行、任务中断后续接 | 优先吸收目标契约、停止条件、隔离和交接格式 |
| Skill 与插件建设 | `effective-agent-skills`、技能创建与改进流程 | 把重复工作沉淀成自己的 Skill，建设个人能力库或团队规范 | 作为设计规范，结合 Codex 原生 Skill/插件机制重写 |
| 深度研究与网页工作 | 深度研究、研究提示、浏览器与网页抓取流程 | 开源项目调研、竞品分析、资料核验、多来源证据整理 | 复用研究框架；数据源、浏览器和 API 按当前工具替换 |
| 工程质量与代码协作 | 代码审查、Bug 修复、工作树、提交与交接 | 功能开发、回归修复、多人/多 Agent 协作、发布前检查 | 与现有 GitHub、测试和浏览器能力组合使用，避免重复封装 |
| 运维、部署与数据访问 | Vercel、Supabase、进程管理、定时任务、只读数据库 | 网站上线、生产排障、数据查询、自动化巡检 | 仅在真实项目出现时启用；先审计账号、写权限和回滚能力 |
| 决策、文档与知识沉淀 | `before-building`、`decisions`、`next-decision` 等 | 需求模糊、方案取舍、架构决策、阶段复盘和跨会话传递 | 优先吸收问题框架和记录格式，写入受版本管理的文档 |
| 安全与权限边界 | 危险命令守卫、只读角色、验证与失败处理 | 引入第三方 Skill、执行外部脚本、接触生产环境或敏感数据 | 作为审计清单和防线参考，不把文本规则当成真正沙箱 |

未来真正需要调用这份储备的信号，不是“某个技能看起来有趣”，而是某类任务开始重复出现、现有能力存在明显空白，或者准备接入新的外部服务和高风险权限。此时再从目录中选择单项能力进行本地化和验证。

## 当前结论

| 维度 | 观察 | 对我们的判断 |
|---|---|---|
| 覆盖范围 | 5 个类型、47 个技能 | 适合作为全面索引 |
| 可移植性 | 18 个技能带 Codex 配置，但大量内容仍绑定 macOS 或作者工具链 | 格式可移植不等于流程可直接运行 |
| 确定性资产 | 2 个技能脚本、5 份 references，绝大多数逻辑仍在 Markdown | 主要价值是方法与经验，不是软件组件 |
| 外部依赖 | DeepAPI、OpenRouter、Fireflies、Supabase、Vercel、Herdr、Pi、cmux 等 | 必须按需启用并单独评估费用与权限 |
| 安全性 | 含守卫、只读和验证思想，也含推送生产、删除/杀进程等动作 | 任何安装都需要逐项审计 |
| 许可证 | MIT | 允许学习、修改和再分发，但仍需保留许可声明 |

## 建议使用方法

```text
出现真实重复任务
→ 在分类目录中找到候选技能
→ 检查与现有 Codex 技能/插件是否重叠
→ 审计脚本、网络、密钥、写入和破坏性动作
→ 替换作者专属路径、工具、模型和项目约定
→ 用 3–5 个正向/反向样例测试触发与执行
→ 只安装通过验证的单个技能
→ 记录来源、版本和本地改动
```

## 优先阅读清单

1. `effective-agent-skills`：技能设计、渐进加载、测试和安全。
2. `goal-loop`：为长任务定义目标、约束、验证和停止条件。
3. `git-worktree`：多代理并行时隔离代码和运行环境。
4. `handoff`：跨会话保留决策、进度和剩余工作。
5. `research-prompt`：把研究问题写成可验证的研究任务。
6. `before-building`、`next-decision`、`decisions`：在实施前后暴露隐藏决策。
7. `global-agent-guardrails`：研究跨代理的命令安全层，但不直接照搬黑名单。

## 不应误解为

- 不是新的基础模型，也不会提升模型参数能力；
- 不是 47 个都已在 Windows 和 Codex 上验证过的插件；
- 不是安装后无需 API Key、账号、费用或本机工具；
- 不是安全沙箱的替代品；
- 不是我们的长期记忆，除非技能把结论写入受管理的持久文件；
- 不是当前项目已经采用的能力清单。

## 研究边界

本次工作只进行了公开源码和文档审计，没有安装或执行上游技能，没有使用任何 API Key、账号、生产数据库、浏览器登录态或付费服务。网页展示的是能力地图和采用判断，不是运行成功率证明。

## 重新深入的触发条件

当某项工作在至少两个真实项目中重复出现，并且现有技能或插件不能稳定解决时，再选取一个候选技能做本地化、测试和安装。不要为了“以后也许会用”而扩大默认上下文、权限或依赖面。
