# Yichen Skills 研究归档

上游仓库：[mcncarl/yichen-skills](https://github.com/mcncarl/yichen-skills)

公开专题页：[Yichen Skills 能力与平台技术地图](https://yydshly.github.io/0807_githubcode_study/yichen-skills.html)

## 阶段结论

**不建议把整个仓库作为总项目的核心能力继续深入或直接集成。** 搜索编排、摘要、文案分析、ASR 路由、知识库和草稿上传大多属于通用 Agent 能力，并且上游许可证仅允许个人学习和非商业使用。

值得保留的是它对中文内容平台的经验性技术路线：X、小红书、抖音、微信公众号、小宇宙、B站和 YouTube 在搜索入口、登录要求、正文读取、媒体下载、失败回退和风控边界上存在显著差异。这些信息可作为后续平台接入的调研起点，但任何正式接入仍需独立验证和自行实现。

## 对总项目的意义

- 补齐此前未系统研究的中文内容平台入口地图。
- 建立“搜索发现”和“已知链接读取/下载”分离的架构认知。
- 参考统一候选结构、来源追踪、归档清单、防覆盖和断点恢复设计。
- 识别匿名访问、浏览器登录态、账号令牌、付费 ASR 与平台风控的不同边界。
- 为未来的统一内容工作台准备平台适配器清单和标准化交接字段。

## 本次没有做什么

- 未克隆、安装或执行上游 Skill。
- 未读取任何用户账号、Cookie、Token、收藏或私人数据。
- 未运行小红书、抖音、微信、X 或小宇宙的登录态抓取。
- 未部署后端服务、数据库、定时任务或付费 ASR。
- 未验证上游脚本在当前 Windows 环境的成功率和长期稳定性。

因此本研究属于**公开源码与文档层面的能力审计和技术归档**，不是运行验收。

## 重新开启专项研究的条件

只有满足以下任一条件时，才建议对具体平台继续投入：

1. 产品路线明确需要该平台的公开内容或用户授权内容。
2. 已确定数据用途、平台条款、访问频率、凭据管理和商业许可方案。
3. 可以为适配器建立固定样例、失败分类、回归测试和健康度监控。
4. 需要把该平台接入统一候选、归档或内容工作台，而不是一次性抓取。
