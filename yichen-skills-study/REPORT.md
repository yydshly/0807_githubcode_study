# Yichen Skills 阶段研究报告

## 研究问题

本次围绕四个问题展开：

1. 这个仓库的核心能力是什么？
2. 不同信息平台如何搜索、读取和下载？
3. 抓取后怎样归档、分析、再创作和展示？
4. 哪些内容对总项目有持续参考价值？

## 核心判断

Yichen Skills 是一套“Skill 工作流程 + 本地脚本 + 外部工具”的个人内容生产工具集。Skill 负责识别意图、选择路线、规定授权和输出格式；Python、Node、Playwright、ffmpeg、yt-dlp、Grok CLI、OpenCLI、ASR 服务和浏览器登录态负责真正执行。

它的能力链可以概括为：

```text
研究目标
→ 平台差异化搜索
→ 标准候选清单
→ 用户确认
→ 已知链接读取/下载
→ 本地归档
→ ASR与内容分析
→ 图片/视频/草稿输出
→ Obsidian或Agent Memory沉淀
```

上层能力多数通用；平台接入细节是本次最有价值的部分。

## 具有参考价值的设计

### 1. 平台差异化路由

不把所有平台当成普通网页：公众号使用公开索引或本地 exporter，小红书和抖音站内搜索依赖浏览器状态，X 优先 Grok 原生搜索，B站和 YouTube 使用结构化 CLI，小宇宙全站发现依赖网页索引。

### 2. 搜索与下载解耦

搜索只产生候选；只有用户给出的 URL、明确选择的候选或精确容器才能进入读取与下载。私人收藏导出也只输出 URL，不自动继承媒体下载授权。

### 3. 统一候选和证据来源

不同后端结果映射为统一字段：平台、查询、标题、URL、作者、时间、类型、互动指标、可见性、验证状态、来源后端和限制。摘要是线索，打开原文后才可标记为已核验。

### 4. 安全归档

默认不覆盖、不删除，冲突时创建新运行目录；批量处理记录成功、失败、跳过与不支持项；部分路线通过来源元数据、文件大小和 SHA-256 判断是否可恢复。

### 5. 授权不可转移

一次登录态读取、私人收藏导出或媒体下载授权，只对当前平台、关键词、链接和当前任务有效。标准交接记录授权状态，但交接本身不产生新授权。

## 抓取后的能力

- 输出 Markdown、HTML、JSON、文本、图片、音视频、SRT 和口播稿。
- Step/豆包 ASR 路由，支持全文、时间戳、字幕与口播粗剪。
- 对标视频十三模块拆解，重点是标题、开头、爆点、逐句作用、结构、表达效率和可模仿模板。
- X 帖子生成 3:4 图片、ZIP 和固定模板视频。
- Markdown 上传到 X Article 草稿，不点击最终发布。
- 对话保存到 Obsidian；Agent Memory 使用 Markdown、SQLite FTS 和可选语义索引。

这些能力中，文案拆解和知识沉淀主要依赖大模型与流程说明；只有部分平台下载器、X切片和草稿上传具有较明确的确定性执行代码。

## 对总项目的决策

| 决策 | 结论 |
|---|---|
| 整库集成 | 不建议 |
| 继续全面运行验证 | 当前不投入 |
| 平台技术路线归档 | 建议保留 |
| 数据模型与交接协议 | 可借鉴 |
| 上游脚本直接用于商业产品 | 不建议，受许可证和稳定性限制 |
| 未来专项接入 | 按真实产品需求逐平台重新验证 |

## 许可证与可靠性边界

上游使用个人学习和非商业许可，禁止未经书面许可用于创收业务、客户交付、内部公司工具和再打包。部分平台路线依赖页面 DOM、非官方接口、浏览器登录态或第三方索引，可能随平台更新失效。仓库的安全规则值得参考，但不能替代独立安全审计、平台合规评估和运行验证。

## 最终意义

本项目不是新的核心组件，而是一份有用的平台工程参考样本。它把“平台从哪里搜、已知链接怎样读、媒体怎样取、失败如何回退、授权怎样隔离”整理成可执行 SOP。总项目应吸收这些方法和字段语义，避免复制整库；未来有真实平台需求时，再从对应技术卡片开始专项实验。
