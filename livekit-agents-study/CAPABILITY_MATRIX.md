# LiveKit Agents 能力矩阵

这份矩阵把三件事分开：LiveKit Server 负责实时房间与媒体；LiveKit Agents 负责 AI 参与者、会话和工作流编排；模型或外部系统提供识别、推理、合成和业务数据。

| 能力域 | LiveKit Agents 中的核心机制 | 可以怎样扩展 | 本项目证据 | 后续实验 |
|---|---|---|---|---|
| 实时入房、任务与媒体 | `AgentServer`、命名 Worker、显式 dispatch、房间 Job、`load_fnc`、进程执行器、restart policy、`RoomIO` | Worker 池、容量阈值、拒绝/重派、边缘部署 | 已验证：两个同名 Worker 对两个房间按可用负载分单；单 Job 或整个 Worker 故障不杀其余服务；本地 `ON_FAILURE` 30 秒未自动跨 Worker 替代且 API 状态陈旧；显式替换 Dispatch 后由幸存 Worker 恢复 | 可靠自动重派、退避队列、Worker 心跳仲裁、滚动升级与跨机部署 |
| 语音流水线 | `AgentSession` 编排 VAD → STT → LLM → TTS | 任意兼容厂商、本地模型、Fallback、Realtime 模型 | 已验证：小米 MiMo ASR + MiniMax M3 + MiniMax TTS | 流式 ASR、自然打断、端到端 Realtime 对照 |
| 回合管理 | 端点检测、打断、抢占生成、转录同步 | 单轮互斥、全双工、降噪、语义断句 | 已验证：稳定单轮、状态与阶段指标 | 打断准确率与误触发评测 |
| 工具调用 | `@function_tool`、结构化参数、工具结果回写上下文 | 数据库、搜索、业务 API、设备控制、RAG | 已验证：`get_room_status` 读取真实房间 | 带参数工具、错误恢复、权限控制 |
| Agent 交接 | 工具返回新的 `Agent`，SDK 执行 handoff 并保留会话上下文 | 专家路由、分层客服、审批流、任务分工 | 已验证：研究向导 ↔ 工作流专家 | 三角色路由与交接质量评测 |
| 长任务与工作流 | Agent/Task、参数化工具、共享会话状态 | 预约、工单、访谈、分步采集、人工接管 | 已验证：收集 → 审核 → 人工审批门 → 批准/拒绝；待审批跨房间恢复，本机 SQLite identity 隔离、乐观并发与追加式审计 | 服务端认证、审批 RBAC、生产数据库、不可篡改审计与超时升级 |
| 多模态 | 房间视频轨道、`rtc.VideoStream`、`llm.ImageContent`、数据通道与多模态模型 | 视觉巡检、远程协助、屏幕理解、虚拟人 | 已验证：确定性 640×360 合成视频经 LiveKit 发布，Agent 回报帧数、尺寸与哈希；同一帧交给 MiniMax M3 后正确识别“橙色、三角形、742” | 屏幕共享、按需抽帧策略、连续场景变化、视觉工具调用与隐私遮罩 |
| 电话与外部渠道 | SIP/电话参与者、房间路由 | 呼入客服、外呼通知、坐席转接 | 尚未实现 | 本地 SIP 或测试号码接入 |
| 可观测性与评测 | 会话事件、dispatch/job/worker/participant 状态、`/worker`、metrics、trace、测试框架 | 延迟、容量、成本、成功率、转写质量、工具准确率 | 已观察单一 Dispatch `running` 会与 Agent 缺席、Worker active jobs=0 矛盾；页面已做多信号健康判断 | 结构化记录 P50/P95、心跳、重试次数、队列时间、并发量、成功率和成本 |

## 场景思考方法

不要从“做一个语音聊天机器人”开始，而从下面五个问题判断是否值得使用这个库：

1. 谁在同一个实时房间里：用户、AI、人工坐席、设备或其他 Agent？
2. 输入输出是什么：语音、文字、视频、电话，还是它们的组合？
3. Agent 除了回答，还必须调用什么真实工具或完成什么任务？
4. 何时需要交给另一个专家、人工或长期工作流？
5. 用什么指标证明可用：首字/首声延迟、任务成功率、打断成功率、转写准确率、成本或合规性？

## 适合优先探索的场景

- 实时客服与人工接管：AI 先接待，识别意图后交给专家或人工坐席。
- 语音业务助手：在对话中查询订单、创建工单、预约或操作设备。
- 访谈与陪练：持续记录上下文，由不同角色进行提问、评估与反馈。
- 远程协作与视觉助手：与用户共享音视频，并结合屏幕或摄像头内容调用工具。
- 电话 Agent：把 SIP 电话也视为房间参与者，复用同一套会话和工作流。

目前最重要的结论是：LiveKit Agents 的差异不在“能调用一个大模型”，而在于它把 AI 变成可加入实时房间、管理语音回合、调用业务工具、跨角色保持任务状态并接受调度和观测的服务端参与者。
