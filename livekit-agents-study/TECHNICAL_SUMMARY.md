# LiveKit Agents 技术总结与产品能力说明

## 一句话结论

**LiveKit Agents 是 LiveKit 实时应用中 AI Agent 的运行与编排核心。**

它不是大模型，不是 LiveKit 音视频服务器，也不是整个产品的业务控制面。它负责把 AI 变成一个能够加入 LiveKit 房间、处理文字与媒体、管理对话回合、调用工具、切换 Agent 角色，并接受 Job/Worker 调度和观测的服务端参与者。

它最重要的价值不是“又封装了一次模型 API”，而是让模型进入真实的实时通信环境。再配合应用自己的状态、权限、审批和业务接口，才可以把一次模型回答升级成可执行、可恢复、可运营的业务过程。

## 四类组件怎样协作

```text
用户 / 网页 / App
        ⇅ 文字、音频、视频
LiveKit Server
        ⇅ Room、Participant、Track、Data
Agent Worker（LiveKit Agents / AgentSession）
        ├─ 调用模型服务：ASR、LLM、视觉、TTS
        └─ 调用业务工具：知识库、日历、CRM、工单、审批 API
```

这不是“模型再调用业务系统”的串行链路。LiveKit Agents 位于中心：一侧连接 LiveKit 房间，另一侧分别编排模型和业务工具。

| 组件 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| LiveKit Server | 房间、参与者、WebRTC、音视频轨道和数据通道 | 不负责模型推理和业务决策 |
| LiveKit Agents | AI Participant、AgentSession、回合、工具调用、handoff、Job 与 Worker | 不自带模型，也不替代业务数据库、权限和审批系统 |
| 模型服务 | ASR 识别、LLM 推理、视觉理解、TTS 合成 | 不负责房间传输和业务事实源 |
| 业务系统 | 用户、订单、预约、知识库、权限、审批和真实操作 | 需要由应用通过工具/API 接给 Agent |

## LiveKit Agents 库自身具备什么

1. **实时 AI 参与者**：Agent 可以像用户或人工坐席一样加入 LiveKit Room，订阅和发布文字、音频、视频。
2. **语音流水线编排**：`AgentSession` 组合 VAD、STT、LLM、TTS，也可以换成端到端 Realtime 模型。
3. **回合管理**：处理说话开始与结束、生成、播放、抢占、打断和转录同步等状态。
4. **工具调用**：通过结构化 Function Tool 访问数据库、搜索、RAG、业务 API 或设备。
5. **Agent handoff**：同一会话可切换到不同指令和工具集的专家 Agent，并保留上下文。
6. **会话与上下文原语**：提供会话状态、对话上下文、事件和工具钩子，应用可以在其上构建多步骤工作流。
7. **任务调度与运行**：使用 AgentServer、Worker、Job、命名 Agent 和 Dispatch 分配房间任务。
8. **多模态媒体接入**：订阅房间中的文字、音频和视频轨道；应用决定哪些帧或转录需要交给模型。
9. **可观测性**：观察参与者、Dispatch、Job、Worker、工具、handoff、延迟和会话事件。
10. **模型与 I/O 扩展点**：可替换 STT、LLM、TTS、Realtime 模型和 Room I/O 实现。

需要特别注意：STT、LLM、TTS、视觉模型和业务数据不是 Agents SDK 自带能力；审批门、SQLite 持久化、RBAC 和业务审计也不是 SDK 开箱即用功能。本项目使用 Function Tool、handoff、会话事件和自建业务状态把它们组合成了研究原型。

多人可以处于同一个 LiveKit Room，但“自动总结整个群聊或视频会议”不是当前原型已验证的开箱能力。常见语音 `AgentSession` 会围绕一个关联参与者处理输入；会议场景还需要应用显式聚合多名参与者的轨道/转录、区分说话人、处理加入离开和权限，再把整理后的上下文交给 Agent。

## 配合其他能力后能形成什么产品效果

| 配合能力 | 产品效果 |
| --- | --- |
| 流式 ASR 或 Realtime 模型 | 边说边出字、更低首字延迟、自然打断和连续对话 |
| LLM | 意图理解、推理、工具选择、回复生成和专家路由 |
| 多模态模型 | 理解摄像头、商品、设备、文档或共享屏幕 |
| CRM、ERP、工单、日历 API | 查询订单、创建预约、修改工单并执行真实操作 |
| RAG 与企业知识库 | 根据内部资料提供可追溯回答 |
| 登录、租户与 RBAC | 确认身份，限制数据、工具和审批权限 |
| 人工坐席系统 | AI 接待后携带上下文和任务状态转给人工 |
| SIP/电话 | 呼入客服、外呼提醒、电话预约和坐席转接 |
| 数字人 | 把语音 Agent 表现为讲解员、导购或服务形象 |
| 监控与评测 | 统计延迟、成功率、准确率、成本和异常 |
| 多参与者聚合与说话人识别 | 总结群聊或会议，提取发言人、结论和跨参与者待办 |

## 适合优先产品化的场景

### 1. AI 预约与业务接待助手

这是当前最接近产品化的方向。语音/文字接待、信息收集、角色交接、人工批准、恢复和审计已经有完整原型。

### 2. 实时客服与人工接管

AI 先接待和查询业务系统，复杂、高风险或低置信度问题交给专家 Agent 或人工坐席。

### 3. 远程视觉协助

用户展示设备、商品或现场画面，Agent 按需分析，并连接知识库、工单或售后系统。

### 4. 语音工单和现场作业助手

边沟通边收集字段、生成工单，并要求人工确认关键操作。

### 5. 面试、访谈、培训与陪练

不同 Agent 分别承担提问、评估、反馈和总结，并持续保存任务状态。

### 6. 电话 Agent

接入 SIP 后，复用现有语音、工具、handoff、审批和审计能力。

## 判断是否应该使用这个库

适合使用 LiveKit Agents 的信号：

- 场景需要实时语音、视频或电话；
- 用户、AI、人工坐席或多个 Agent 需要处于同一实时空间；
- Agent 除了回答，还必须调用真实工具完成任务；
- 任务需要角色交接、人工审批、暂停和恢复；
- 需要观察延迟、容量、失败、工具执行和业务结果。

如果需求只是普通文本问答、离线批处理或单次模型调用，直接调用模型 API 往往更简单。

## 当前边界与未接入项

- 小米 MiMo 当前是停顿后上传整句音频；SSE 流式返回文字不等于音频帧实时输入。
- 当前采用稳定单轮模式，主动关闭自然打断和预生成。
- 视觉是按需分析最新一帧，不是连续视频理解。
- 当前原型只验证了浏览器与一个 Agent 的主要交互链路，没有验证多人会议的全员转录聚合、说话人区分和会议总结。
- 预约只写入本机 SQLite，没有连接真实日历、CRM 或预约系统。
- 浏览器 identity 不是正式登录；本地审计不是不可篡改审计。
- Worker 故障已验证显式恢复，但没有证明可靠自动重派。
- 尚未验证跨机器 Worker、分布式事务、心跳仲裁和滚动升级。
- SIP、电话、录制、完整屏幕共享和数字人尚未接入。
- OpenAI Realtime 只有模板，没有真实模型验收。
- 没有生产 TLS、TURN/TLS、Redis、监控、防火墙和公网部署。
- 尚未完成弱网、规模并发、长期稳定性、成本和质量评测。

## 推荐的产品化顺序

1. **产品外壳**：简化用户端，只保留开始对话、字幕、任务卡、确认和转人工；研究字段移入实验室或管理端。
2. **实时体验**：按需求接入真正的流式 ASR，随后再研究自然打断和弱网体验。
3. **业务闭环**：连接一个真实日历、CRM 或工单系统，加入可信身份和 RBAC。
4. **生产控制面**：补齐可靠队列、自动重派、跨机 Worker、集中监控、成本和质量评测。
5. **渠道扩展**：按业务价值接入 SIP、屏幕共享、数字人或更多模型。

当前阶段应先把能力和产品形态讲清楚，保留研究控制台作为技术证据；新的模型和生产能力按真实业务需求再接入。
