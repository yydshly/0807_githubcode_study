WHAT THE LIBRARY ACTUALLY DOES

它不是模型，而是实时 AI 的运行与编排层。

理解这个库的关键，是区分房间、Agent、模型和业务系统四类组件。它们不是从上到下的串行流水线；Agents 在中心连接房间，并分别调用模型和业务工具。

01 · TRANSPORT

LiveKit Server

房间、参与者、WebRTC、音视频轨道与数据通道。

回答：人和媒体怎样实时连接？
02 · ORCHESTRATION

LiveKit Agents

AI Participant、回合、工具、角色交接、Job 与 Worker。

回答：AI 怎样在连接中工作？
03 · INTELLIGENCE

模型服务

ASR 识别、LLM 推理、视觉理解和 TTS 合成。

回答：AI 怎样听、想、看和说？
04 · ACTION

业务系统

用户、知识库、预约、工单、审批、权限与真实数据。

回答：这次对话最终完成什么？
→

核心差异：普通模型 API 只生成内容；LiveKit Agents 负责 AI 在实时通信中的运行与编排，业务结果仍由应用自己的工具、状态和权限系统完成。

WHERE IT FITS

优先选择“实时交流 + 真实任务”的场景。

如果只是普通文本问答，直接调用模型 API 更简单；当场景需要媒体、工具、交接和长期状态时，这个框架的价值才会明显。

01 · HIGH FIT

AI 预约与接待

信息收集、审核、人工批准、恢复和审计已经形成原型闭环。

02 · HIGH FIT

实时客服与人工接管

AI 先处理意图与工具，复杂问题携带完整上下文交给专家或人工。

03 · MEDIUM–HIGH

远程视觉协助

用户展示设备或现场画面，Agent 按需分析并联动知识库与工单。

04 · MEDIUM

现场作业与语音工单

边沟通边补全字段、生成记录，并把关键操作交给人工确认。

05 · MEDIUM

访谈、培训与陪练

多个角色持续提问、评估和反馈，保留会话与任务状态。

06 · FUTURE

电话 Agent

配合 LiveKit SIP 后，可复用现有语音、工具、handoff 与本项目业务流程。

PRODUCTIZATION ROADMAP

先做一个业务闭环，再按需要优化实时性。

当前不新增流式 ASR。下一次优化应由明确的产品场景、用户量、延迟目标和合规要求触发。

  1. 现在能力说明与产品外壳

    把研究成果转成产品可理解的价值、流程和边界。

  2. 按需求连接一个真实业务系统

    优先选择日历、CRM 或工单中的一个，验证任务成功率。

  3. 体验瓶颈出现后流式 ASR 与自然打断

    用真实延迟和用户行为决定是否替换当前稳定单轮。

  4. 准备上线时身份、权限与生产控制面

    补齐 RBAC、可靠调度、监控、成本、弱网和合规。

NEXT DECISION

现在不需要再堆模型，先选择一个值得完成的业务任务。

研究控制台保留全部技术证据。后续只有当产品场景明确需要更低延迟、电话、连续视觉或生产规模时，再继续对应方向。
