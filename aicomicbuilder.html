PRODUCTION SYSTEM REVIEW · 2026/08/09

它不是导演。它是把AI短剧生产流程固定下来的执行系统。

AIComicBuilder 管理项目、分集、角色、分镜、关键帧和视频资产，并自动调用模型；ChatGPT/Codex 负责故事、导演、审批、审片与返工。

01 / CAPABILITY MAP

从剧本文件到可管理的镜头资产

它的价值不是某一条提示词，而是让每个生成阶段拥有结构、状态、版本和下一步动作。

01

文本生产

大纲、剧本、自动分集、角色提取和分镜拆解。

能生成初稿，不评价戏剧质量
02

视觉资产

角色参考、场景参考、首尾帧和镜头提示词。

一致性取决于Provider
03

短视频

首尾帧或参考图驱动4–15秒镜头，支持外部网页接力。

表演与微动作需要审片
04

项目管理

项目、分集、分镜版本、镜头资产和活动版本。

适合单机研究与小型制作
05

自动控制

计划、审批、执行、幂等、重试、取消和并发控制。

本地Codex控制分支已实现
06

合成输出

FFmpeg拼接、字幕、下载和素材打包。

不是专业剪辑与混音系统
02 / CONTROL PLANE

把创作判断放在流水线之外

模型负责产出候选结果；控制层决定是否调用、是否接受以及失败后改提示词还是改导演方案。

04 / MODEL INTEGRATION

统一接口不代表模型能力相同

人物一致性最容易被“界面看似有参考图”误导；必须确认具体Provider是否真的发送了参考图片。

模型/入口合理职责关键边界
MiniMax M3剧本辅助、提取、分镜、图片/视频理解不是视频生成模型
MiniMax image-01角色与关键帧候选当前只保留第一张主体参考
Gemini图片多参考图一致性当前内置路线最完整
外部视频网页人工替代Video Provider不能规模化自动运行
05 / LIMITS

技术成功不等于镜头合格

真人花店实验的眼神插值失败，证明自动审片比继续增加模型调用更重要。

剧本

能生成，不能负责

没有完整解决冲突升级、人物弧线、分集钩子和可拍摄性。

一致性

依赖具体Provider

部分图片适配器没有实际发送角色参考图。

表演

眼、手、口型高风险

优先用剪辑表达，避免独立人脸首尾帧做微表情插值。

可靠性

仍是本进程任务

重启不能续跑；长故事需要持久队列和Provider任务查询。

合成

预览级而非后期级

缺镜头仍可能部分合成，非硬切路径会移除镜头原声。

规模

SQLite + 本地文件

适合单机研究；多人生产需要认证、对象存储和审计。

NEXT ARCHITECTURE

AI编剧室 → AIComicBuilder生产执行 → 自动审片与返工

下一阶段不应只是生成更多样片，而应增加系列圣经、连续性账本、镜头风险分类、视觉/音频QA和可恢复任务队列。
