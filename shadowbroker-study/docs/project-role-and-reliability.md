# ShadowBroker 的作用与数据可靠性边界

## 一句话定位

ShadowBroker 是一个多领域公开数据聚合、统一地图展示和辅助分析平台。

它把飞机、船舶、卫星、灾害、新闻、基础设施、无线电和网络安全等不同来源放进同一界面，帮助用户快速理解公开信息所呈现的全球大概布局。

它不是雷达系统、卫星控制系统、空管系统、军事指挥系统或权威灾害发布平台。

## 它真正做的事情

```text
公开 API / Feed / 网页 / 社区接收网络 / 可选本地设备
                         ↓
                  定时拉取或持续订阅
                         ↓
              格式转换、去重、缓存和推断
                         ↓
                 地图、列表、时间线和告警
```

核心价值包括：

1. 用一个入口观察多个公开领域。
2. 展示目标和事件的空间分布与大概变化。
3. 提供 REST、WebSocket、TCP、MQTT、RSS、STAC 等接入案例。
4. 帮助发现值得继续核验的目标、异常和来源。
5. 作为公开来源研究、Connector 设计和数据治理的样本项目。

## “实时”应该怎样描述

不应笼统地写成“实时全球监控”。更准确的表述是：

> 项目包含部分近实时公开数据流，也包含分钟/小时轮询、低频目录、延迟遥感产品和本地推算数据。地图刷新速度不等于原始数据真实、完整或刚刚发生。

项目中的数据大致分为：

| 类型 | 例子 | 能否称实时 | 可靠性边界 |
|---|---|---|---|
| 连续公开流 | AISStream、APRS、MQTT | 可称近实时 | 只代表网络收到的消息，仍可能缺失、错误或断线 |
| 高频轮询 | 飞机、地震、警报 | 分钟级近实时 | 受上游刷新、配额、接收覆盖和缓存影响 |
| 低频轮询 | 新闻、摄像头目录、金融、元数据 | 不宜称真正实时 | 可能延迟数分钟到数天 |
| 轨道推算 | CelesTrak TLE/OMM → 卫星位置 | 不是实时观测 | 根据已发布参数计算，参数老化和机动会带来误差 |
| 遥感产品 | Sentinel、SAR、GIBS | 通常不是实时 | 经过过境、下传、处理和发布 |
| 新闻/规则推断 | 航母、冲突事件、GPS 干扰 | 不是直接观测 | 需要原始证据、交叉验证和置信度 |

## 为什么数据“不全”

- 有些目标不广播、关闭设备或不在公共网络覆盖范围内。
- 聚合商可能过滤敏感目标、隐私目标或高成本字段。
- 免费接口有配额、延迟、区域限制和无 SLA 问题。
- 同一个目标在不同来源中的 ID、字段和时间可能不一致。
- 网页、非正式 API 和社区服务会变更或下线。
- 轨道和遥感属于参数/产品发布，不是持续现场连接。
- 新闻、众包和派生结果存在重复、误报、偏见和证据不足。

因此“没有显示”只能说明：

> 当前启用的来源没有返回这个目标。

不能直接推出：

> 这个目标不存在，或者现场没有发生事件。

## 正确用途

- 了解公开数据中的全球分布。
- 做态势感知和线索发现。
- 比较多种公开来源和接入协议。
- 研究数据采集、清洗、溯源、去重和可视化。
- 为后续专业系统选择数据源和验证架构。

## 不适合的用途

- 航空管制、航行安全或救援决策。
- 精确军事目标跟踪。
- 依赖秒级完整性的自动控制。
- 把地图上的所有点当作直接实时观测。
- 根据单一公开来源作出高风险结论。
- 未核对许可就进行商业化或数据再分发。

## 推荐展示标签

每个地图对象应明确显示：

```text
来源
数据类型：直接观测 / 目录推算 / 新闻推断
observed_at：原始观测时间
published_at：上游发布时间
fetched_at：本项目获取时间
置信度
是否为备用源
是否可能延迟、过滤或过期
```

最终定位可以写成：

> ShadowBroker 汇集多领域公开来源，提供全球对象和事件的大概空间布局、近实时线索及历史/背景信息。部分数据来自持续流或分钟级轮询，部分来自延迟产品和轨道/规则推算；其结果不能视为完整、权威或无遗漏的实时监测。
