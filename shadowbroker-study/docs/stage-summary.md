# ShadowBroker 阶段研究总结

> 审计与运行日期：2026-08-07  
> 阶段状态：研究完成，作为“信息获取与展示类产品”参考案例归档  
> 上游基线：提交 `8676a98945a31503180bc84f7c9dd092a3cc743d`，v0.9.84

## 一句话结论

ShadowBroker 值得用于了解多来源信息采集、协议接入、时空展示和来源可靠性技术方向，但当前没有继续深入改造成完整全球实时监控系统的必要。

以后遇到卫星地图、灾害监测、全球新闻、船舶态势或行业情报等信息获取与展示产品时，可以按需参考其中的局部架构和接入方式，不建议整体照搬。

## 它是什么

ShadowBroker 是一个多领域公开数据聚合和统一地图展示平台。

```text
公开 API / Feed / 网页 / 社区接收网络 / 可选本地设备
                         ↓
                  轮询、订阅或设备推送
                         ↓
              转换、去重、缓存和部分推断
                         ↓
                 地图、列表、时间线和告警
```

它可以帮助理解公开信息中的大概空间布局和变化线索，但不是雷达、空管、测控、航行安全、军事指挥或权威灾害发布系统。

## 已完成的工作

- 初始化研究总仓库并建立独立 `shadowbroker-study` 子项目；
- 拉取并核对 ShadowBroker 上游源码快照；
- 在 Windows 本地以源码方式运行前端和后端；
- 验证中文界面、主要地图图层和本地健康接口；
- 审计数据源、协议、免费条件、设备入口和部署要求；
- 归档卫星、航空、船舶、灾害、新闻、GDELT、无线电和其他领域覆盖；
- 核对卫星数量、轨道计算、AIS接入和Time Machine实现；
- 整理 P0、P1、P2 技术路线和未来子项目拆分方式。

## 本地实际效果

当前审计期间已验证：

- 前端：`http://127.0.0.1:3000`；
- 后端：`http://127.0.0.1:8000`；
- 核心地图可以运行并显示多类数据；
- 中文属于部分本地化，仍有英文设置和弹窗；
- 免费来源会出现限流、授权失败、源失效和数据量波动；
- 应用健康状态变红不一定代表程序崩溃，也可能是部分上游来源失败。

运行环境、依赖和错误详见 [本地部署与实际效果报告](local-deployment-report.md)。

## 对数据完整度和实时性的理解

### 卫星

- 界面中的约 490 颗卫星是军事、雷达、资源、天气、导航和科研等六个公开专题分组，不是全球卫星总数；
- 审计当天 CelesTrak `active` 公开目录约有 16,301 条；
- 项目下载公开 OMM/轨道参数，使用 SGP4 推算当前位置；
- 地图移动是本地计算效果，不是卫星直接向项目持续上报坐标；
- 适合观察公开轨道的大概布局，不适合测控级定位和任务状态判断。

### 船舶

- 全球船位主要依赖 AIS 岸基接收网络、卫星 AIS 和聚合服务；
- 当前本地没有配置 AISStream Key，看到的 11 艘主要来自缓存和静态线索，不能代表全球船舶；
- 小船、关闭AIS的目标、军舰、覆盖空洞和身份欺骗都可能导致缺失；
- 船旗国可以从 MMSI 推断，领海和 EEZ 需要额外边界数据做空间匹配。

### 飞机

- ADS-B协议公开，但“全球完整数据”依赖大量接收站和聚合商；
- 免费接口存在限流、授权、覆盖和隐私过滤；
- 地图中的飞机数量随来源状态明显波动，不能作为全球航空总量。

### 地震、天气、新闻和 GDELT

- 地震和官方天气预警通常是最值得优先研究的公开近实时来源；
- 新闻和 GDELT 适合事件线索与趋势整理，不是现场直接传感器；
- GDELT存在转载重复、媒体偏差、地名解析和事件推断误差，必须保留原始报道和证据链。

## 对时空控制的理解

项目当前实现的是：

```text
最新状态刷新
+ 前端运动插值
+ 15/120 分钟压缩快照
+ 时间轴快照回放
+ 浏览器视口裁剪
```

它还不是完整的时空数据库：

- 快照时间不等于每条记录的真实观测时间；
- 快照间位置是线性插值，不是真实轨迹；
- 历史主要保存为gzip JSON；
- 服务端空间过滤当前实际未生效，主要由前端裁剪；
- 尚未统一实现 `observed_at / published_at / fetched_at`；
- 尚未实现国家、领海、EEZ和争议区空间匹配。

因此可以参考交互和快照思路，但正式产品应重新设计追加式观测存储、时空索引和历史状态重建。

## 最值得参考的技术路线

### P0：数据基础

- 来源注册与许可治理；
- 可插拔来源适配器；
- REST、RSS、WebSocket、TCP、MQTT和设备HTTP推送；
- 对象、事件、位置和三个时间字段；
- 缓存、重试、限流、来源健康度和备用源。

### P1：领域能力

- OMM加SGP4卫星轨道计算；
- 国家、行政区、领海和EEZ空间增强；
- 新闻/RSS/GDELT去重、实体和事件管线；
- 历史轨迹、快照和回放；
- 全量数据的聚类、网格、视口裁剪和WebGL展示。

### P2：按需增强

- 跨来源实体关联；
- 目标异常、身份异常和来源异常告警；
- AIS、ADS-B等边缘接收节点和多点融合。

完整说明见 [P0–P2 技术路线整理与说明](p0-p2-technical-route-guide.md)。

## 当前不继续深入的部分

- 不继续为“全部卫星、全部船舶、全部飞机”改造现有项目；
- 不逐个申请并长期维护全部上游密钥；
- 不深入 InfoNet、Wormhole 和自动组网实验；
- 不投入不稳定摄像头目录、预测市场和边缘图层；
- 不把现有 Time Machine 扩建成正式时空数据库；
- 不把整个 ShadowBroker 直接作为未来产品基础代码。

## 未来什么情况下重新开启

出现以下具体需求时，再回来抽取相关路线：

- 建设卫星全量公开目录和轨道地图；
- 建设地震、天气、火灾等灾害监测产品；
- 建设全球新闻与GDELT事件平台；
- 建设AIS船舶、港口、领海或EEZ态势产品；
- 建设需要REST、长连接、MQTT或本地设备统一接入的信息平台；
- 建设带历史回放、空间查询和来源证据的行业情报系统。

重新开启时应独立建立小型专题项目，只抽取需要的协议、数据模型或展示思路。
