# ShadowBroker 是否需要部署：决策与深入研究评估

> 评估日期：2026-08-07

## 1. 直接结论

你现在不需要把 ShadowBroker 做成公网服务，也不需要先做多点部署。

但值得进行一次“单机、本地、只读、最少来源”的沙箱部署。它的价值不是长期使用这个成品，而是亲眼观察完整链路：外部源如何失败、调度器如何轮询、长连接如何重连、数据如何统一、缓存怎样工作、浏览器还会联系哪些第三方。

推荐边界：

- 不开放到公网，只监听本机。
- 不启用实验性的 InfoNet/fleet join。
- 不启用 LiveUAMap 浏览器规避抓取。
- 不连接交易、写入或主动扫描能力。
- 首轮只用公开只读源和你自己的测试 Key。
- 先记录外联、错误、429、响应字段和时间语义，再看地图效果。

## 2. 按研究目标判断是否部署

| 研究目标 | 完整部署 | 多点部署 | 更合适的方法 |
|---|---:|---:|---|
| 整理有哪些公开来源 | 不需要 | 不需要 | 源码审计 + 官网条款核对 |
| 学习 REST/RSS/CSV/STAC | 不需要 | 不需要 | 为每种协议写小型探针/适配器测试 |
| 理解整个抓取—清洗—缓存—展示链路 | 值得单机部署一次 | 不需要 | 本地沙箱 |
| 做长期个人情报看板 | 需要单节点常驻 | 通常不需要 | 只启用选定来源，增加监控与缓存 |
| 自己覆盖某港口的 AIS | 中心可部署 | 一个当地边缘点 | AIS-catcher → HTTPS POST → 中心 |
| 自己覆盖多个机场/港口/无线电区域 | 中心需要 | 需要 | 多个轻量边缘接收节点 + 一个中心 |
| 主动做全球网络测量 | 不一定是 ShadowBroker | 可借 RIPE Atlas | 使用现有 Atlas 探针，必要时再托管探针 |
| 公网多人使用或商业化 | 需要正式架构 | 视覆盖目标 | 先完成许可、安全、成本和隐私评估 |

## 3. 为什么现阶段不建议公网部署

1. 来源授权不统一。公开可访问不代表允许持续自动化、商业使用或二次分发。
2. 外联面很大。后端会请求大量 API/Feed，前端还会直接请求地图瓦片和媒体。
3. 凭据多。环境变量包含航空、AIS、遥感、摄像头、金融等多个 Token，误提交或日志泄露风险高。
4. 网页抓取不稳定。LiveUAMap、Telegram 预览、部分摄像头和非正式金融接口会随页面变化。
5. 数据质量不等于地图精美。聚合源会重复、延迟、漂移或修订，派生位置更需要置信度。
6. 当前电脑没有 Docker Desktop。源码方式可以运行，但一次性验证前还要安装 Python/Node 依赖；没有必要先扩大部署面。

## 4. 推荐四阶段路线

### 阶段 0：静态来源审计

当前已完成首轮：记录来源、入口、协议、认证、设备需求和免费类型，并锁定上游源码提交。以后每次升级项目都用新提交重新做差异扫描。

产出：来源台账、官方条款链接、代码入口、最后核验日期。

### 阶段 1：协议实验室

不启动整套应用，分别验证代表性入口：

- HTTP/GeoJSON：USGS。
- RSS/Atom：选一个官方公告源。
- 静态 CSV：OurAirports。
- TLE + 本地计算：CelesTrak。
- WebSocket：AISStream 免费 Key。
- 原始 TCP：APRS-IS 接收模式。
- MQTT：Meshtastic，保持默认关闭，单独测试时再启用。
- OAuth2：OpenSky 或 Copernicus。
- STAC：Planetary Computer。

每个实验只保存少量原始样本和响应头，不批量镜像上游数据。

### 阶段 2：单机 ShadowBroker 沙箱

目标是验证集成，不是“把所有图层点亮”。建议先只启用：USGS、CelesTrak、NOAA、一个 RSS、公开静态设施；再逐个加入 Key 型来源。

观察项：

- 启动需要哪些服务和内存。
- 后端实际发出的域名、请求频率和响应量。
- 429、超时、断网后是否退避，而不是立即重试风暴。
- 同一个飞机/事件在主源和备用源间如何去重。
- 页面打开后浏览器直接连接哪些瓦片、图片和视频域名。
- 关闭某个来源后，旧数据何时过期和从地图消失。

### 阶段 3：选择一个垂直领域重做

最有研究价值的不是继续堆来源，而是选一个领域做干净的“来源框架”。例如航空：

```text
OpenSky / Airplanes.live / adsb.lol
              ↓
       connector 统一接口
              ↓
原始留存 → 标准化 → 去重 → 质量评分
              ↓
       查询 API → 地图/时间线
```

验收标准应是可溯源、可解释、能处理失败和许可，而不仅是地图能显示点。

### 阶段 4：只有问题需要时才加设备和多点

当研究问题变成“公共源看不到我关注区域”“我要比较自有接收与聚合源的延迟”“我要在断网环境采集”时，再加入边缘节点。

中心与边缘建议拆开：

```text
边缘节点：天线/SDR → 解码 → 本地队列 → 签名上传
中心节点：认证 → 去重 → 原始存档 → 标准化 → 展示
```

边缘节点不需要运行完整 ShadowBroker UI，也不应直接持有中心所有 API Key。

## 5. 首轮本地沙箱配置边界

保持以下实验能力关闭：

```env
MESH_INFONET_FLEET_JOIN=false
MESH_MQTT_ENABLED=false
SHADOWBROKER_ENABLE_LIVEUAMAP_SCRAPER=false
GT_ANALYTICS_ENABLED=false
```

再遵循四条规则：

- 所有 Key 放本机未跟踪的环境文件，绝不写入文档、截图或 Git。
- 服务只绑定 `127.0.0.1`，除非后续明确做局域网测试。
- 第一轮不填 Shodan、金融、浏览器自动化和写入型凭据。
- 为每个源设置显式开关；缺 Key 时应跳过，而不是循环报错。

当前环境有 Node.js 22 和 Python 3.10。2026-08-07 已完成源码依赖安装和真实启动：前端 `127.0.0.1:3000`、后端 `127.0.0.1:8000` 均返回 HTTP 200。没有 Docker Desktop，本次采用源码方式。详细实测见 `local-deployment-report.md`。

## 6. 最需要深入研究的 10 个点

| 优先级 | 研究点 | 要回答的问题 | 建议产物 |
|---|---|---|---|
| 1 | 来源治理与许可 | 谁拥有数据？自动化、商业、缓存和再分发允许吗？ | `source-policy.yaml` + 最后核验日期 |
| 2 | 统一 Connector 契约 | REST、WS、TCP、MQTT 怎样暴露相同的健康和数据接口？ | Connector 接口与样例适配器 |
| 3 | 时间与新鲜度 | 观测、发布、抓取、展示时间分别是什么？ | 四时间字段规范 + 延迟指标 |
| 4 | 溯源与置信度 | 地图上的每个点能否回到原始源？派生结果如何标记？ | provenance/confidence 模型 |
| 5 | 调度、限流与背压 | 429、断线、慢消费者和备用源切换怎么办？ | 调度策略、退避、熔断测试 |
| 6 | 去重与实体解析 | 同一飞机、船、地点、新闻如何跨源合并？ | 稳定实体 ID 与合并规则 |
| 7 | 数据漂移 | 字段、网页、目录端点或认证变化怎样被发现？ | Contract tests + 每日健康报告 |
| 8 | 安全与隐私 | 自定义 URL 是否可造成 SSRF？Token、前端外联和媒体代理安全吗？ | 威胁模型、域名 allowlist、秘密管理 |
| 9 | 边缘设备协议 | 节点身份、断网缓存、重传、时钟和覆盖如何处理？ | 边缘上报协议 v1 |
| 10 | 成本与可替换性 | 免费层失效后是否有备用源？出口流量和存储多大？ | 月成本模型 + 主备源矩阵 |

## 7. 你的研究价值判断

对你最有价值的是四层，而不是 ShadowBroker 的整套 UI：

1. 来源目录：发现一个领域有哪些原始机构、社区聚合商、开放数据和付费增强源。
2. 接入协议：学习 REST、Feed、批量文件、WebSocket、TCP、MQTT、STAC、地图瓦片和设备推送。
3. Connector 框架：把不同来源统一为可配置、可观测、可替换的采集模块。
4. 来源治理：许可、时效、质量、失败、溯源和隐私。

数据清洗和展示当然重要，但应该排在“入口是否可靠、合法、可持续、可验证”之后。ShadowBroker 最适合作为来源与协议的样本库、反例库和集成测试对象，而不是直接作为你所有研究项目的固定底座。

## 8. 最终建议

- 现在：保留本地上游快照，完成入口台账，不公网部署。
- 下一步：做 6–8 个代表协议的最小连接实验。
- 然后：单机运行一次 ShadowBroker，捕获真实外联和失败行为。
- 再后：从一个领域重建你自己的通用 Connector 框架。
- 最后：只有当自有地域覆盖是研究目标时，才购置设备并做多点边缘部署。

完整来源入口见 `docs/source-entry-guide.md`，机器台账见 `data/source-catalog.csv`。
